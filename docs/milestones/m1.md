# M1 — Classic CYOA

## Scope and acceptance criteria

M1 turns the M0 stub into an authored, offline CYOA runtime. All four accepted
ADRs and the M0 dependency policy remain in force. No model, graph generation,
intent classification, NPC controller, editor, or graphics subsystem is included.

1. **CYOA-01:** A versioned story definition has an ID, title, start node, typed
   initial variables, nodes, structured authored content, choices, conditions,
   effects, target nodes, and explicit endings. IDs are unambiguous. A reusable
   engine accepts a definition rather than hardcoding the reference adventure.
2. **CYOA-02:** Load YAML from a file with syntax locations and file context.
   Reject unknown fields, duplicate IDs, absent starts/targets, invalid content,
   undeclared variables, incompatible types, invalid endings, unreachable nodes,
   and nodes with no structural path to an ending. Explain the offending node,
   choice or variable. Malformed definitions never create a playable engine.
3. **CYOA-03/04:** Only currently executable choices are projected. Shared pure
   one-transition previews exclude target-condition deadlocks and effect overflow.
   The engine
   revalidates IDs, conditions and revisions; applies effects in authored order;
   and commits variables, target and revision together. Invalid actions,
   arithmetic overflow, and transitions leaving a non-ending with no offers
   leave state unchanged. Boolean, signed integer and string variables support
   equality, integer comparisons, boolean combinations, assignment and checked
   integer addition. Evaluation is deterministic and does not interpolate prose.
4. **CYOA-05:** Semantic output contains narrative/dialogue blocks and explicit
   ending metadata, not formatted screens. The text adapter preserves authored
   prose exactly and formats dialogue/ending labels. Only visible content and
   eligible offer labels reach the presentation layer, never variables or the
   full story definition.
5. **CYOA-06:** `grimm-cli play stories/the-last-witness.yaml` plays complete
   adventures, handles invalid numbers and EOF, and reports actionable load and
   runtime failures. The no-argument M0 demo remains a regression command backed
   by the same engine. CLI session commands `:save PATH`, `:load PATH`, `:quit`
   are handled at the composition root, not parsed as game actions.
6. **CYOA-07:** JSON saves have schema version 1, story ID and authored version,
   node ID, typed variables and revision. Engine-issued snapshots are separate
   from presentation. Restore rejects unsupported versions, wrong stories,
   missing/extra/mistyped variables, unknown nodes and non-endings without an
   executable transition.
   Invalid loads preserve the active session. Saving/restoring a mid-game or
   ending session reproduces narrative/offers and subsequent deterministic
   behavior. Restore never reuses an active engine revision, so old actions stay
   stale even when loading an older checkpoint.
   Saves are editable local checkpoints, not cryptographically authenticated
   proofs of past play; authors must bump story versions for incompatible edits.
7. **CYOA-08:** The Last Witness has investigation and withdrawal routes,
   conditional evidence/trust choices, meaningful effects, and at least two
   distinct endings. Automated complete playthroughs prove every ending, plus
   branch/condition behavior and restored continuation. README gives exact
   interactive and scripted commands.
8. Existing M0 regression tests retain their behavioral assertions (updated only
   for the documented structured-content protocol migration and explicit ending
   display). New tests cover
   invalid YAML/definitions, typed conditions/effects, atomic rejection, stale
   actions, serialization, checkpoint validation, CLI save/load, and privacy.
   Cargo dependency checks still forbid engine-to-adapter/renderer edges and
   renderer-to-semantic edges. CI runs formatting, Clippy, workspace tests, and
   offline M0/M1 demos. Finish with a reviewable PR against main; do not merge.

## Implementation plan

1. Extend provisional semantic types with structured content and explicit ending
   metadata, authoring definitions and checkpoint types. Document the breaking
   M0 `text` to `content` migration. Keep all private definitions/checkpoints out
   of `SemanticOutput` and out of adapter interfaces.
2. Add engine-owned definition validation, deterministic expression/effect
   evaluation, atomic traversal and validated checkpoint restore. Retain the M0
   demonstration as a two-node definition using this same runtime.
3. Update the authored text adapter; add YAML and JSON codecs/file handling only
   to the CLI composition root. Use `serde_yaml_ng` for YAML and existing
   `serde_json` for saves; the engine still depends only on semantic types.
4. Write The Last Witness, schema documentation, tests and reproducible commands.
   Run semantic diagnostics, formatting, Clippy, workspace tests and demos; fix
   failures, audit acceptance coverage, commit, push and create the PR.

## Boundary and compatibility decisions

There are no new crates or reversed dependency edges. Authoring and checkpoint
DTOs live in separate semantic modules: they are host/engine inputs and outputs,
not player-visible projections. The composition root may serialize them; adapters
only consume `SemanticOutput`. Engine state remains private and every definition,
action and restored state is validated by the engine. This implements accepted
ADRs rather than changing them; no additional boundary approval is required.

Story schema version 1 and save schema version 1 reject unknown versions. There
were no M0 story files or saves to migrate. M0 consumers construct narrative
blocks instead of `SemanticOutput.text`; rendering moves entirely to the adapter.
The structured projection explicitly distinguishes an ending from a deadlock.
The text adapter appends `Ending: TITLE`, including in the M0 demo; its original
welcome, choice, completion prose and input behavior are preserved. The M0 tests
now construct content blocks and expect this additional ending label.

## Implementation report and acceptance evidence

The six-crate layout is unchanged. `grimm-semantic::story` defines authoring DTOs;
`grimm-semantic::save` defines checkpoints; `grimm-engine` validates both and owns
all transitions. The CLI loads YAML with `serde_yaml_ng` and saves JSON with
`serde_json`. Neither format library is an engine, adapter, or renderer dependency.

| Requirement | Automated evidence |
|---|---|
| CYOA-01 | `engine/tests/runtime.rs`: reusable graph traversal, explicit endings and cycles with exits |
| CYOA-02 | Runtime invalid-definition tests; `cli/tests/classic.rs`: malformed YAML, unknown fields, duplicate variables, invalid operations and contextual errors |
| CYOA-03 | Runtime hidden/stale/forged action rejection and reference offer tests |
| CYOA-04 | Typed expression validation, boolean combinations, checked/ordered effects, overflow and deadlock rollback |
| CYOA-05 | Adapter exact-prose/dialogue/ending test; structured projection and serialization tests |
| CYOA-06 | Actual CLI processes play all endings, retry input, handle EOF, report file errors and run the M0 demo |
| CYOA-07 | Mid-game/ending checkpoint round-trips, invalid restore preservation, CLI in-session load and startup resume |
| CYOA-08 | Full playthroughs cover justice, exile and silence plus the route without evidence |
| M0 boundaries | Cargo dependency policy, state-privacy doctest, renderer tests and forged-projection regression remain active |

Run the three verification commands in README and its scripted ending commands.
The CLI's host commands never become engine actions; failed loads preserve the
current session and its offers. Unknown schema versions fail explicitly; no
implicit save migration exists. See [story-format.md](../story-format.md) for
authoring semantics and versioning responsibilities.

Local validation: `cargo fmt --check`,
`cargo clippy --workspace --all-targets --locked -- -D warnings`, and
`cargo test --workspace --locked` pass (39 tests including the privacy doctest).
The offline build, original M0 demo and all three scripted reference endings
also pass. LSP diagnostics timed out/stayed stale; RustRover inspections returned
no reported problems but some timed out, and its build tool could not collect
diagnostics. Cargo provides the authoritative build/test results.

## Deferred questions

Cross-session asynchronous action identity, protocol negotiation, save migration
beyond version 1, rich content/assets, and semantic validation of generated prose
remain deferred. Static validation checks graph structure and expression types;
it does not solve all possible variable assignments. Single-transition previews
protect immediate condition-dependent transitions, not global route solvability.
Longer-range blocked states and state-changing cycles can still arise; the CLI
reports an explicit error if filtering leaves a non-ending without executable
offers. See the story-format guide for this horizon and revision-exhaustion
behavior. No new public types or dependency edges are introduced by this fix.
