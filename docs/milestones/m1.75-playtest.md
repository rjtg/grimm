# The Last Train: authoring and playtesting

## Adventure and routes

The independent thriller has 14 nodes, three explicit endings, two timed scenes
and an untimed opening/investigation. Rowan Bell's emergency call lasts 15 real
seconds. The platform decision lasts 20. Both clearly state the stakes and show
an indicator; all investigation scenes allow unlimited real deliberation.

Fictional minutes are separate. A tower search costs 15; the quick fuse route
arrives prepared with evidence at minute 17, while documenting every wire
arrives with the same evidence/preparation at minute 21. Only the first can
make the controlled stop (window: through minute 18 inclusive). The tunnel plus
Rowan's log verification and the independent maintenance-carriage route each
arrive at minute 9. Losing Rowan's call removes the log-verification choice but
does not prevent independent investigation or an explicit evacuation ending.

| Ending | Example semantic choice route |
|---|---|
| A Red Light in Time | answer-phone → reassure-rowan → search-tower → hurry-to-fuse → fit-fuse → controlled-stop |
| The Price of Warning | answer-phone → reassure-rowan → search-tower → document-every-wire → fit-fuse → clear-platform |
| The Last Green Signal | answer-phone → reassure-rowan → run-to-platform → trust-green; alternatively allow the platform timeout |

Call expiry enters an authored untimed `call_lost` scene, rather than forcing a
technical failure or inventing an ending. It has a guaranteed evacuation exit
and an independent-investigation option. Platform expiry commits the authored
disaster ending. No generated content, offscreen simulation or NPC planning is
involved. The bounded checker reports 89 states, 130 choice inspections and all
three endings without a nonterminal deadlock, within its documented limits.

## Actual terminal sessions

I played the actual CLI with a terminal, reading prompts and submitting choices
one at a time, rather than considering native tests a sufficient playtest.

1. **Successful temporal route:** read the untimed opening, lifted the phone,
   paused the live call and saved `/tmp/grimm-train-human.json`. Loaded that
   checkpoint in the same session, observed the Paused state, resumed and
   answered Rowan while the visible counter was still above ten seconds. Took
   the service tunnel, restored the circuit, and verified the log. At the
   platform, the controlled-stop choice was available. Paused and resumed that
   live deadline too, then selected the controlled stop while more than sixteen
   seconds remained. The CLI displayed **A Red Light in Time** and exited.
2. **No-input timeout:** started a second terminal session, lifted the phone and
   deliberately submitted nothing with stdin still open. The indicator counted
   down through 0.9 seconds; the engine then entered the authored lost-call scene
   without requiring a newline. Selected its evacuation option and reached
   **The Price of Warning**. This demonstrates actual host-clock expiry, not a
   manual-clock test pretending to be realtime.
   After binding reads to prompt revisions, I repeated the no-input session:
   the lost-call scene explicitly requested Enter, the old read was discarded,
   and a subsequent evacuation choice reached the same ending. A new timed
   scene would remain unready until that acknowledgement.

Temporary checkpoint paths above are observations, not committed fixtures.
Automated real-host tests additionally exercise expiry with open stdin and EOF,
and pause/save/load/resume after longer wall time than the original short test
deadline, for both active and paused checkpoints. A two-prompt host regression
also waits past the new deadline before acknowledging the old read, proving it
does not activate early or reinterpret that input as a new choice.
Core temporal tests only submit explicit observations; they never
sleep or read a clock.

## Gameplay assessment and friction

The first author-run playtest is coherent and tense enough for external testing.
The untimed opening explains lifecycle commands before urgency starts. The call
uses a brief request, and the platform offers an unconditional evacuation action
so lack of evidence is a meaningful cost rather than a deadlock. The slow tower
route tests the difference between complete evidence and timely evidence.
This is not independent evidence of enjoyment or accessibility.

- Countdown lines are recognizable but basic: terminal echo can interleave with
  indicator refreshes. No raw-terminal animation or cursor-control dependency is
  introduced. A later presentation improvement could redraw one status line.
- Timed prompts must stay short. Pause is intentionally permitted for reading,
  saving and accessibility; the engine does not attempt to enforce dramatic
  pressure against the player's explicit pause choice.
- Saving is not pausing. The opening recommends pausing first. A resumed or
  loaded decision must be presented again before counting its preserved budget.
- An outstanding line belongs to one prompt revision. After an asynchronous
  change, Enter acknowledgement safely clears that read before the new prompt
  activates. The real-host test driver waits for prompts; deterministic native
  game tests use semantic IDs and explicit Ready/Elapsed inputs.
- World chronology is private canonical state, not a UI dump. Authored labels
  explain costs and the 18-minute window. Optional authored public clock displays
  can be considered later if a game needs them; no hidden state is exposed now.
- One test fixture initially used an unquoted comma inside a YAML flow mapping;
  schema loading rejected it correctly. The fixture was corrected rather than
  relaxing strict authoring validation.

## Decisions deliberately kept small

No offline catch-up, independent frontend clocks, generic scheduler, time-driven
NPC controller or simulation is included. Timeout effects are typed assignments;
arithmetic is reserved for ordinary validated actions. Non-ending timeout targets
must have an unconditional effect-free, zero-cost exit to an ending. This gives
authors an explicit reliable consequence without a full fallback-solvability
solver. Normal counter exhaustion remains an explicit transactional error rather
than wrapping state. OS input scheduling is not a hard realtime fairness claim.
The stdin reader is a one-session CLI process driver, not a reusable cancellable
I/O service for embedding hosts. Embedders can use the same explicit engine
inputs with their own lifecycle-aware I/O instead of adding a runtime framework
to the core.
