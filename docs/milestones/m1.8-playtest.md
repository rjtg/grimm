## Game design

13 authored nodes: storm → carrier (consecutive narrative-only segments), gated
12-second emergency, optional lost-call consequence, untimed investigation with
archive/engineer/battery routes, narrative briefing, gated untimed final choice,
and three explicit endings. These are different situations aboard the same
station, not an entity framework or parallel progress graph.

The two opening segments establish isolation and then reveal the threatening
voice. The emergency gate gives the player time to understand the relay and
stakes before starting pressure. The final gate is untimed: consequences deserve
deliberation, not another reflex check. Timers are selective rather than universal.

| Route | State/consequence | Ending |
|---|---|---|
| Answer, archive, send live bearing | Trust + evidence | A Voice That Answers |
| Isolate, archive, independent bearing | Reserve power + evidence | A Voice That Answers |
| Answer, reconstruct with Imani | Trust unlocks evidence route | A Voice That Answers |
| Prepare power, sever link | Crew/coast survive, vessel lost | The Cost of Silence |
| Follow the voice | Guidance beam admits the threat | An Open Door |
| Emergency expires, evacuate | Lost reply and trust; intentional retreat | The Cost of Silence |

Every state retains explicit retreat and risky-beam outcomes. The timeout is not
a deadlock: it enters an authored lost-call scene with investigation or evacuation.
The bounded checker observes all three endings in 39 states / 53 edge inspections
with no nonterminal deadlocks found (not an exhaustive solvability claim).

## Authoring findings

`continue_to` removes dummy choices while keeping an obvious linear successor.
One acknowledgement per scene lets several paragraphs form a coherent reading
unit; splitting every sentence would make the CLI tedious. The consecutive
opening segments each make a substantive new reveal, rather than padding count.
`presentation_required` gates a scene's own prose without duplicating it in a
separate fake-choice node. The author does not specify cinematic seconds.

The three existing variables were sufficient for trust, evidence and preparation.
No new conditions, effects, entity store, location framework or simulation were
needed. Continuations deliberately have no effects; state changes remain legible
at meaningful choices. Existing timeout safety restrictions remain compatible.

Friction: a gate currently covers all required prose in one node; there is no
partial paragraph/audio checkpoint. Loading pending presentation replays that
whole node. The CLI has a second Enter after an old asynchronous read is discarded
if the successor also has required storytelling: the first cannot stand in for
the newer segment's own acknowledgement. This favors correctness over polish.
Countdown text can interleave with terminal echo. Authors should explain pressure
and timeout consequences in required prose, because the timer begins as soon as
the resulting choices are usable.

## Actual terminal evidence

Author-run CLI playtest, not independent feedback on enjoyment/accessibility:

- Started the actual `cargo run --locked -p grimm-cli -- play
  stories/the-silent-signal.yaml` command in a terminal. Enter advanced storm
  and carrier without numbered Continue choices.
- At emergency prose, left the session waiting for more than the configured
  12-second deadline, including a measured 14-second no-input wait. No offers,
  countdown or expiry appeared. Saved `/tmp/grimm-signal-reading.json` while
  reading: node emergency, phase Presenting, world minute 0, 12,000 ms remaining.
- Enter then displayed both choices and **12.0s**. Left stdin open and silent.
  The active countdown expired into the lost-call scene. Enter discarded the
  old pending read, then choice 2 reached **The Cost of Silence**. No hidden
  state was printed to the player.
- Reopened the actual CLI with `--load /tmp/grimm-signal-reading.json`.
  Emergency prose replayed, with no choices or running deadline before Enter.
  This provides an actual process boundary for pending-presentation restoration.
- In that restored terminal session, completed reading, paused the newly opened
  decision, then resumed and answered the captain. Took archive → kept the safe
  bearing, acknowledged the narrative briefing and untimed final gate, and sent
  the trusted bearing. Reached **A Voice That Answers**, with both required Enter
  prompts visibly separate from meaningful numbered choices.

Automated process tests additionally cover full timely routes to each ending,
reading beyond a short deadline before both timely action and real expiry,
pending-reading pause/resume/save/load, EOF during initial narration and a gated
successor, stale Enter/commands, all legacy playthroughs, and the existing Train
timing/lifecycle tests. Core lifecycle tests use only explicit deterministic
events, never sleeps or clocks; real-host tests use bounded short durations.

Recommendations for later milestones: preserve these completion/readiness
boundaries when adding speech or panels; consider partial presentation checkpoints
only with an actual frontend need. Independent reader testing should assess prose
clarity and the emergency's time budget. No visual runtime, cinematic controls,
generative narration, free-text intent, timeline or scheduler is introduced here.
