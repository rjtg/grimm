# M0 — Architecture Foundation: coding-agent brief

## Objective
Establish all major architectural boundaries **before** story features are built. Deliver a tiny working round trip; avoid speculative infrastructure.

## Scope
1. Create minimal Cargo workspace with distinct crates/modules for engine core, semantic protocol, presentation protocol, adapter contracts and a CLI composition root. Exact crate count is flexible if dependency rules are mechanically enforceable.
2. Define minimal serializable types for game action, semantic output, interaction offer, and presentation command. Keep the type set deliberately small.
3. Implement stub engine that accepts one action and produces a semantic output; a plain-text output adapter; a CLI renderer/input adapter. Demonstrate a complete round trip.
4. Add tests proving action routing and separation of engine state from presentation state.
5. Add CI checks for formatting, Clippy, and tests. Document build/run commands.
6. Enforce dependency direction by workspace dependency checks or another automated mechanism.

## Acceptance criteria
- `cargo test --workspace` passes.
- A CLI command starts the demo, displays a line and a choice, accepts input, and returns an engine-produced result.
- No engine crate imports UI/Bevy/LLM SDK dependencies.
- Presentation adapter cannot directly mutate engine state.
- Documentation explains how a future LLM text adapter or Bevy adapter can be added without changing core dependencies.

## Out of scope
Full story graph, YAML DSL, persistence, NPC simulation, model integration, browser frontend, plugin system, graphics. Those belong to later milestones.

## Deliverables
Focused PR, passing tests, short architecture notes, runnable demo instructions, list of unresolved decisions.
